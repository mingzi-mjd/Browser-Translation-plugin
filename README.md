# 双语翻译

在浏览网页时保留原文、读懂译文，也能随时翻译一段文字或正在输入的内容。

支持 **Google、Microsoft、OpenAI、Anthropic**，可连接兼容协议的本地 AI 服务。提供网页双语对照、划词翻译、独立文本翻译页面和本地翻译缓存。

> 当前版本：**0.0.1**。面向 Chrome、Edge 和 Firefox 桌面浏览器，采用手动加载方式安装。

## 功能一览

| 功能 | 可以做什么 |
| --- | --- |
| 双语网页 | 在原文下方显示译文，支持动态内容和一键还原 |
| 划词翻译 | 选中文字后，在鼠标附近点击按钮查看译文 |
| 文本翻译 | 输入或粘贴文字，查看、复制译文，也可在独立页面使用 |
| 翻译网页输入框 | 翻译搜索框、评论框等已有内容，预览后替换，并支持撤销 |
| 命名格式复制 | 将译文复制为小驼峰、大驼峰、下划线或短横线格式 |
| AI 引擎配置 | 自定义接口、模型、系统提示词、Temperature 和输出上限 |
| 本地翻译对照表 | 复用已翻译内容，减少重复等待和接口调用 |
| 视频双语字幕 | 支持 YouTube、哔哩哔哩普通视频已有字幕，提前缓冲并显示原文和译文 |
| 通用视频听译 | 独立采集标签页声音，连接本地语音识别服务生成字幕后翻译，无需网站字幕接口（Chrome / Edge） |

## 通用视频听译（独立功能）

此功能与下方的 YouTube / B 站已有字幕翻译独立，可以分别开启和停止。它直接识别当前标签页播放的声音，适用于大多数普通视频网站，也适用于音频页面；无需下载视频或导入文件。第一版支持 Chrome / Edge，Firefox 的原有翻译功能继续保留。

1. Windows 用户推荐按 [原生语音识别服务说明](local-asr/README.md) 安装并启动，无需 Docker；NVIDIA 显卡可用 faster-whisper CUDA，AMD / Intel 显卡可按 `local-asr/README.md` 的「AMD / Intel GPU（Vulkan）」一节启动。也可继续使用 [Speaches](SPEACHES.md)。等待多语言识别模型加载完成。
2. 重新加载插件并刷新目标视频页。**在目标页点击浏览器工具栏的插件按钮 → 通用视频听译 · 语音识别服务**，打开独立控制窗口。
3. 填写基础地址（默认 `http://127.0.0.1:8000/v1`）、模型 ID，以及可选的 API Key。点击「获取可用模型 / 检查连接」查看结果。此操作不会自动安装模型。
4. 选择自动识别或手动指定原语言，选择翻译引擎、目标语言和 2 / 3 / 4 / 6 / 10 秒最长音频分段（默认 2 秒，停顿时提前发送）。也可选择「只识别，不翻译」。翻译引擎复用原来的配置。
5. 点击「开始听译当前视频」，按浏览器提示授权服务地址，然后返回视频页播放。**控制窗口必须保持打开**，可以切到后台；关闭窗口即停止采集。
6. 网页上的「通用听译」字幕可拖动、调节字号或停止。控制窗口显示音频缓冲、识别结果、处理耗时和积压情况。

悬浮窗也有独立入口，但浏览器可能要求先通过工具栏操作授予目标标签页采集权限。如提示拒绝采集，请从目标页的工具栏插件按钮重新进入。

**运行方式与限制：**

- 本地服务接收单声道 WAV，通过 `/v1/audio/transcriptions` 返回识别结果。连续说话按时长截断时保留约 0.25 秒重叠，停顿分段时不重叠，过滤较安静的片段，并对边界重复文字做有限去重。
- 这是边播放边听译，延迟包含音频分段、识别和翻译耗时，不能提前读取尚未播放的音频。短片段、多语言混说、低音量或背景音乐可能影响识别效果，可手动指定原语言。
- 识别最多 1 段正在处理、1 段等待，超过后丢弃最旧等待段以追上播放；因此服务性能不足时会漏掉部分内容，并在状态中显示丢弃数量。识别 90 秒超时或接口出错后停止采集，由用户检查后重新开启。翻译与识别分开调度，最多 1 个翻译请求和 1 段最新待译文本，过期译文不会覆盖新原文；较慢引擎可能导致跳过译文。控制窗口分别显示采集、排队、识别和翻译耗时。旧配置的默认 6 秒首次升级会切换为 2 秒，之后可手动调整。
- 同时只运行一个听译会话。刷新、导航或关闭目标页会停止。顶层页面可访问的音视频暂停、跳转和倍速变更会清空旧缓冲；跨域 iframe 内播放控制可能无法检测，必要时手动停止后重开。
- 采集的是**整个目标标签页**的声音，多个视频、广告或提示音会混在一起；不采集麦克风。浏览器内置页面、禁止采集的媒体、受保护视频不保证支持。
- 普通页面和容器全屏可显示字幕；直接让 `<video>` 或跨域 iframe 进入原生全屏、系统画中画时，页面字幕层可能不可见，可退出原生全屏或查看控制窗口结果。
- 音频只发送到配置的语音识别服务，不保存音频文件。语音识别服务配置（含可选 Key）保存在扩展来源的本地存储，网页内容脚本不接收密钥。转写文字发送到选定翻译引擎；使用本地 AI 接口可使识别与翻译均在本机完成。原有翻译缓存及清理功能继续适用。
- **无痕模式**：先在 `chrome://extensions` 打开扩展详情并启用「允许在无痕模式下运行」。听译控制窗口和提前缓冲后台页会跟随目标标签页所在的无痕窗口，不会跳到普通窗口。无痕与普通窗口的扩展授权/存储是否共享取决于 Chrome 的扩展无痕模式；如果语音识别地址或 API Key 为空，请在该窗口重新填写。

这版按用户要求未进行自动化或浏览器实测，需安装后验证实际网站和本地服务兼容性。

### 提前缓冲听译（实验模式）

实时听译继续保留。新增模式会打开同一视频的第二个页面，在后台采集、识别和翻译，将带时间戳的字幕暂存在内存中；前台依据自己的播放进度显示。需要先等待一段字幕准备好，再开始观看，不能提高电脑本身的识别速度。

1. 在前台视频页打开工具栏插件 → **通用视频听译**，填写语音识别和翻译配置。
2. 点击 **切换到提前缓冲听译（实验）**。选择后台 **1× / 1.25× / 1.5× / 2×**（默认 2×）和提前采集上限 **1 / 3 / 5 分钟**（默认 3 分钟），两项设置自动保存。启动 / 恢复前只需准备 **5 / 10 / 15 秒**字幕，选择缓冲不足时是否自动暂停。
3. 点击 **打开后台识别页**。前台会暂停，插件打开同一网页的新标签页。
4. 等待后台页的视频加载完成，必要时手动播放片刻。确认是同一视频，没有广告或其他声音。点击该页的浏览器工具栏插件按钮，再点击 **用此页提前识别**。
5. 返回前台观看页。后台声音不会播放给用户，也不会改变前台播放速度；字幕准备好后前台开始播放。控制窗口显示已准备字幕、已采集音频、待处理队列以及后台暂停的具体原因。前台字幕栏的 **−0.5s / +0.5s** 分别让字幕提前 / 延后半秒，**重置**恢复同步；调整范围为 ±30 秒，仅本次提前缓冲会话有效，不会重新识别或改变视频速度。
6. 前台手动暂停时不会强制恢复；拖动进度或改变倍速会清空旧时间轴并重新缓冲。缓冲不足时若开启自动暂停，会等待准备好后继续；未开启则可能暂时无字幕。
7. **停止并关闭后台页** 会释放采集并关闭插件创建的后台页，恢复前台的自动暂停状态；也可点击 **返回实时听译**。请保持控制窗口和后台页打开，任何相关页面关闭 / 导航均会结束会话。

第一版的限制：

- 顶层页面有多个可见 HTML video 时，自动选择**面积最大、可播放的主视频**；两页仍需选到同一视频，时长必须一致。不能只靠时长保证内容相同，仍需用户确认视频及广告情况。
- 暂不适配跨域 iframe、直播、多个同等主播放器、视频自动切换、独立广告时间轴。iframe 内视频请改用实时听译，或打开视频直链到顶层页面；发现播放器来源、时长或播放进度异常会停止并提示，避免继续显示错位字幕。
- 后台按选定倍速连续播放、分段采集，同时按顺序识别和翻译已采集的音频。采集时长和服务返回的字幕时间戳均按后台倍速换算回原视频时间轴。2× 时理论上 1 秒可采集 2 秒视频内容，但收到的是加速语音，可能影响识别准确度；效果不佳时降低至 1.5× 或 1×。识别和翻译速度决定最终字幕准备速度。
- 提前采集和待处理队列均采用分钟级上限，按完整音频段划分，边界可能多出一段。队列已满或达到提前采集上限后暂停后台，消耗至约一半再恢复，减少频繁启停。容量按原视频时间计算；默认最多提前 3 分钟，待处理段数随分段长度和后台倍速调整，不再固定为 4 段。仅在内存中保存当前会话的有限缓冲，拖动进度后会清空旧缓冲。
- 控制窗口分别显示已准备字幕、已采集音频和待处理段数。运行中可以随时关闭「字幕缓冲不足时自动暂停前台」：初次缓冲后视频继续播放，字幕来不及时可能暂时空缺。处理长期慢于播放时，缓冲无法消除等待；初始准备 10 秒字幕可能需要超过 10 秒。
- 服务必须支持 `verbose_json` 并返回 `segments` 时间戳；项目自带 faster-whisper 服务可以提供。时间对齐基于播放器时间和短音频段，仍受浏览器音频采集延迟、网络卡顿和模型时间戳精度影响，不能保证逐帧准确。
- 两页同时存在会增加网络和视频解码开销。后台页由插件控制，请勿手动拖动或暂停它。普通容器全屏字幕显示与实时模式一致，原生 video 全屏 / 画中画仍有限制。
- 与原有 YouTube / B 站字幕翻译保持独立；如同时开启可能出现两套字幕，建议观看时只启用一种。

本模式未运行自动化或浏览器实测，请重新加载插件并刷新视频页后安装验证。

## YouTube 双语字幕

1. 更新扩展后，**刷新 YouTube 视频页**，确保字幕获取脚本已加载。
2. 打开 `www.youtube.com/watch?v=...` 普通视频。播放器右上角点击 **双语字幕**，或通过悬浮窗的 **网页工具 → 视频字幕翻译 · YouTube** 打开设置。
3. 选择翻译引擎、目标语言，点击 **开启 / 重新翻译**。AI 引擎复用「翻译引擎设置」中的接口和模型配置。
4. 获取字幕后，可选择人工字幕或自动字幕轨道。切换轨道、引擎或目标语言会重新开始翻译。
5. 在「字幕样式」中设置字号、背景不透明度及距离底部的位置。设置会保存在本地。
6. 点击 **关闭字幕** 可恢复 YouTube 原字幕。关闭设置面板只隐藏面板，不会停止字幕；切换到另一个视频后需要重新开启。

翻译优先处理播放位置之后约 90 秒的字幕：碎片字幕先按标点、间隔和长度合并，AI 请求每批最多 8 段，最多同时发送 2 个请求。Google / Microsoft 按合并后的句段请求。拖动进度后优先处理新位置，已发送的请求仍可能完成；倍速播放时按视频时间显示字幕。只缓冲观看附近的内容，因此进度不一定达到整段视频的 100%。

字幕翻译复用现有本地对照表，缓存按完整句段和翻译配置匹配。开启「忽略缓存重新翻译」可获取新译文。字幕文本会发送到选定的翻译服务，已有缓存开关、清理功能同样适用。此功能不采集音频、不执行语音识别。

**支持范围：** 桌面 YouTube 普通视频的可读取人工字幕、平台自动字幕；支持播放器全屏、暂停、倍速及拖动进度。第一版不支持直播、Shorts、嵌入其他网站的播放器、画中画字幕、无字幕视频或画面内烧录字幕。

**遇到问题：**

- 获取失败或字幕为空：先在 YouTube 播放器中打开 **CC 字幕**，等待原字幕出现，再点击 **重试失败**。YouTube 的字幕链接、访问限制或播放器更新可能影响获取。
- 显示「当前视频没有可读取的字幕」：确认视频确实提供字幕；没有字幕的视频暂时无法处理。
- AI 翻译失败：检查引擎设置、模型和额度，或者切换 Google / Microsoft。失败后会暂停派发新请求，点击「重试失败」继续。
- 译文暂未出现：当前段会显示原文和「正在翻译…」，待请求完成后补充译文；较慢的本地模型可能需要暂停视频等待缓冲。

## 哔哩哔哩双语字幕

1. 重新加载扩展并**刷新 B 站视频页**。打开 `https://www.bilibili.com/video/BV…/` 或 `av…` 普通视频；建议先登录 B 站。
2. 点击播放器右上角 **双语字幕**，或悬浮窗 **网页工具 → 视频字幕翻译 · 哔哩哔哩**。
3. 选择翻译引擎和目标语言，点击 **开启 / 重新翻译**。获取成功后可以选择可用的人工字幕或平台 AI 字幕轨道。
4. 翻译进度、失败重试、提前缓冲、缓存和样式设置的用法与 YouTube 相同。两个网站分别保存字幕偏好，共用翻译引擎配置和本地对照表。
5. 切换视频或分 P 时，旧字幕会清理，点击开启即可翻译当前视频或当前 P。关闭字幕翻译后恢复播放器原字幕。

部分字幕只有登录后才能读取。若提示获取失败，请先在 B 站播放器中打开字幕、确认原字幕能够显示，再点击 **重试失败**；更新扩展或登录后也可以刷新页面重试。插件通过页面现有登录状态获取当前视频字幕信息，不读取、保存或发送 Cookie 给翻译引擎；发送给翻译引擎的仍然只有字幕文本。

当前仅适配 `www.bilibili.com` 的普通视频及分 P，不支持直播、番剧/影视、嵌入播放器或国际版。烧录在画面里的文字、弹幕不属于可读取字幕；无字幕视频暂不支持。网站接口限制或播放器更新可能影响获取，本版本尚需在浏览器中实际验证。

## 安装

### Chrome / Edge：直接加载项目

无需先安装 Node.js，也无需构建即可体验。

1. 下载本仓库：在 GitHub 点击 **Code → Download ZIP**，然后解压；也可以使用 Git 克隆。
2. 在浏览器地址栏输入：
   - Chrome：`chrome://extensions`
   - Edge：`edge://extensions`
3. 开启 **开发者模式**。
4. 点击 **加载已解压的扩展程序**。
5. 选择包含 `manifest.json` 的项目根目录。不要选择 ZIP 文件，也不要选外层不含该文件的文件夹。
6. **刷新已经打开的网页**，即可看到页面侧边的「译」按钮。

建议将扩展固定到浏览器工具栏，方便随时打开设置或恢复悬浮按钮。

### 使用构建目录安装

如需只包含运行文件的安装目录，先准备 Node.js 20 或更新版本，在项目根目录执行：

```sh
npm ci
npm run build
```

构建后会生成：

| 浏览器 | 安装目录 / 文件 |
| --- | --- |
| Chrome / Edge | `dist/chrome`，按上面的方式加载整个文件夹 |
| Firefox 128+ | `dist/firefox/manifest.json`，按下面的方式临时加载 |

Firefox 安装步骤：

1. 打开 `about:debugging#/runtime/this-firefox`。
2. 点击 **临时载入附加组件**。
3. 选择 `dist/firefox/manifest.json`。
4. 如浏览器询问网站访问权限，请授权需要翻译的网站，然后刷新页面。

Firefox 临时安装会在浏览器重启后失效；永久安装需要按 Firefox 的签名与发布流程处理。Safari 和手机端暂不在本项目支持范围内。

### 更新插件

1. 更新本地项目文件。如果加载的是 `dist` 目录，重新运行 `npm run build`。
2. 在浏览器扩展管理页点击插件的 **重新加载 ↻**。
3. 刷新需要翻译的网页；已打开的设置页、独立翻译页也请重新打开。

继续使用原来的加载目录即可，一般无需卸载重装。卸载扩展可能清除本地设置和翻译缓存。

## 第一次使用

**不配置 AI 也可以使用。**

1. 打开一篇普通网页，例如英文文章。
2. 点击页面侧边的 **「译」**，默认进入 **网页工具**。
3. 选择 **Microsoft** 或 **Google**，将目标语言设为 **简体中文**。
4. 点击 **开启双语网页**。

默认使用 Microsoft，网页和划词默认译为简体中文，网页输入框默认译为英语。Google / Microsoft 免密钥接口的可用性取决于网络和服务状态。

如果只想翻译一段文字，切换到 **文本翻译**，粘贴文字后点击 **翻译文本** 即可。

## 各功能怎么用

### 双语网页

进入 **悬浮面板 → 网页工具**，选择引擎和目标语言，点击 **开启双语网页**。

译文会出现在原文下方，原有链接和格式尽量保留。页面新增或变化的段落也会继续处理。进度中可看到完成段数、本地缓存命中数量和实际请求次数。

点击 **还原网页** 可移除译文并停止派发后续请求。已经发送到服务端的请求可能仍会完成；AI 服务可能照常计费。

网页翻译优先处理当前可见区域。AI 翻译会合并短段落批量请求，并限制并发，减少逐个单词等待的情况。

### 划词翻译

1. 用鼠标选中网页上的文字。
2. 在松开鼠标的位置附近点击 **译选中**。
3. 在浮窗查看译文，或点击 **复制译文**。

键盘选词时，按钮会显示在选区附近。仅选中文字不会发送翻译请求。

如未出现按钮，请检查 **网页工具 → 显示划词翻译按钮** 是否开启。

### 文本翻译

1. 点击悬浮按钮，切换到 **文本翻译**。
2. 在原文框输入或粘贴文字。
3. 选择翻译引擎和目标语言。
4. 点击 **翻译文本**，或按 `Ctrl + Enter`；macOS 使用 `⌘ + Enter`。
5. 查看译文并复制。

点击 **独立页面打开**，可将当前原文带入更大的翻译页面。浏览器工具栏的插件面板也提供 **打开文本翻译** 入口。

单次最多输入 **4000 字符**。修改原文后会清除旧译文，避免将上一次的结果误当作新结果。

#### 复制为代码命名格式

“复制译文”右侧提供四种命名格式。以 `user name` 为例：

| 按钮 | 复制结果 |
| --- | --- |
| 复制小驼峰 | `userName` |
| 复制大驼峰 | `UserName` |
| 复制下划线 | `user_name` |
| 复制-命名 | `user-name` |

格式转换不会修改原译文，也不会自动把中文变成英文。用于代码命名时，可以先将目标语言选为英语。

### 翻译网页输入框

这个功能处理的是**网页上已经存在的输入框**，例如搜索框、评论框或消息输入框。

1. 在网页输入框中输入文字，并点击该输入框。
2. 点击页面右下角的 **翻译网页输入框**。
3. 先查看翻译预览，再点击 **替换输入内容**。
4. 需要恢复时，点击 **撤销替换**。

目标语言在 **网页工具 → 翻译网页输入框 · 译为** 中设置。

如果翻译期间继续修改了原文，插件会拒绝覆盖。普通文本框、搜索框和多行文本框支持直接替换；复杂富文本编辑器通常需要复制译文后手动粘贴。

### 调整、缩小或关闭悬浮按钮

| 操作 | 效果 |
| --- | --- |
| 拖动「译」按钮 | 调整位置并吸附到左右边缘，自动记住位置 |
| 点击面板外部或按 `Esc` | 收起面板，保留悬浮按钮 |
| 点击面板顶部 `−` | 缩小并贴边，保留约三分之一宽度的窄条；点击窄条展开 |
| 点击面板顶部 `×` | 选择关闭范围，再确认关闭 |
| 仅本次关闭 | 当前页面隐藏，刷新后恢复 |
| 此网站永久关闭 | 当前域名下的页面持续隐藏，子域名单独设置 |

想重新显示时，在浏览器工具栏打开插件，点击 **恢复此网站悬浮按钮**，即可取消当前网站的永久关闭设置。

关闭悬浮按钮只隐藏入口，不会自动还原网页，也不会关闭划词和输入框翻译。

## 配置 AI 翻译

从工具栏、悬浮面板或文本翻译区点击 **翻译引擎设置**，即可打开配置页面。

### 1. 填写服务地址和密钥

选择 **OpenAI** 或 **Anthropic**，填写接口基础地址和自己的 API Key。

| 服务 | 基础地址示例 | 协议 |
| --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | Chat Completions |
| Anthropic | `https://api.anthropic.com/v1` | Messages |
| 本地或自定义兼容服务 | `http://localhost:1234/v1` | 须与所选服务协议兼容 |

支持 **HTTP / HTTPS**、本地地址、局域网地址和自定义端口。填写基础地址即可，不要在末尾追加 `/chat/completions`、`/messages` 或 `/models`，也不要把 API Key 写进 URL。

访问自定义接口时，浏览器可能询问地址访问权限；允许后才能获取模型或翻译。当前配置表单要求填写 API Key，具体值以所用服务的要求为准。

### 2. 获取或手动填写模型

1. 点击 **自动获取模型**。
2. 根据进度条和状态提示等待获取完成。
3. 在 **可用模型** 下拉框中选择模型，模型 ID 会自动填入下方。
4. 如果服务不支持模型列表接口，也可以直接填写 **自定义模型 ID**。

获取列表不要求先保存配置，使用的是当前表单中的地址和密钥。修改地址、密钥或切换服务后，需要重新获取列表。

列表由服务商提供，可能包含非文本模型；请选择支持所选对话协议、且账号有权限访问的模型。

### 3. 调整翻译参数

| 设置 | 用途 |
| --- | --- |
| 系统提示词 | 规定翻译风格、术语和输出要求，可自行编辑或恢复默认 |
| `{{targetLanguage}}` | 在提示词中替换为目标语言名称 |
| `{{targetCode}}` | 在提示词中替换为目标语言代码 |
| 发送 Temperature 采样参数 | 默认不勾选，使用模型默认采样；需要时手动开启 |
| Temperature | 值越小，输出通常越集中稳定；0 不保证每次完全相同 |
| 最大输出 Token | 控制单次输出上限；过小可能导致译文被截断 |

OpenAI 的 Temperature 配置范围为 **0–2**，Anthropic 为 **0–1**。部分模型不支持自定义采样，遇到相关参数错误时，请取消勾选。

本项目的 Anthropic 请求使用 `2023-06-01` 兼容版本。网页批量翻译还会附加 JSON 输出要求，用于准确对应各段原文；选择的模型需要能遵循该格式。

### 4. 保存并启用

1. 点击 **保存配置**。
2. 在设置页上方选择默认翻译引擎。
3. 点击 **设为默认引擎**。

也可以在具体翻译面板中单独切换引擎。更改配置后，网页翻译请重新开启；已打开的文本翻译页面请刷新。

AI 服务需要自己的 API 使用权限和额度，费用由服务商收取。本地服务的响应速度取决于所用模型、设备及服务配置。

## 使用本地翻译对照表

插件默认启用本地缓存：**先查对照表，命中直接显示；未命中才请求翻译，成功后自动保存。**

对照表会从安装后的成功翻译逐渐积累，不自带词库，也不会补录旧版本已完成的翻译。

- 精确匹配完整单词、短语或段落，仅去除原文首尾空白。
- 不将已有单词译文拼接成句子，避免语境和语序错误。
- 区分目标语言、引擎，以及 AI 的接口、模型、提示词、采样和输出上限。
- 最多保存 **10000 条**，每条保留 **30 天**；超过容量时淘汰最久未使用的记录。
- 重启浏览器后仍可使用。缓存保存在浏览器扩展数据库中，不是项目目录里的文件。

### 查看或清理缓存

打开 **翻译引擎设置 → 本地翻译对照表**，可以：

- 分页查看原文、译文、引擎和到期时间。
- 删除单条记录。
- 清空全部记录。
- 关闭缓存读写。关闭后旧记录仍保留，需要时可单独清空。

### 强制重新翻译

在文本翻译、悬浮面板网页工具或工具栏中，勾选 **忽略缓存重新翻译**，然后再次执行翻译。

成功后会更新对应的缓存记录；如果缓存已关闭，则不会写入。想比较不同 AI 生成结果时，也可以使用此选项。

## 常见问题

### 安装后没有悬浮按钮？

先刷新网页。如果仍未出现，请确认插件已启用、拥有当前网站的访问权限，并尝试在工具栏点击 **恢复此网站悬浮按钮**。

浏览器设置页、扩展商店等受保护页面不能注入插件。

### 自动获取模型失败？

查看按钮下方的错误提示：

| 提示或现象 | 可以检查的内容 |
| --- | --- |
| 未授权接口地址 | 重新点击获取，并处理浏览器权限提示 |
| HTTP 401 | API Key 是否正确 |
| HTTP 403 | 账号是否有模型列表访问权限 |
| HTTP 404 | 基础地址是否正确；服务是否支持 `/models`，不支持时手动填写 |
| HTTP 429 | 是否限流或额度不足 |
| 超时 / 无法连接 | 本地服务是否启动，端口、网络和接口地址是否正确 |
| 更新后没有反馈 | 重新加载扩展，并关闭后重新打开设置页 |

### AI 网页翻译仍然慢？

首次翻译没有缓存，需要等待服务生成译文。插件已采用可见区域优先、短段落批量请求和有限并发：AI 每批最多 8 段，同时最多处理 2 批。

重复访问时可观察“本地命中”和“实际请求”数量。如果命中为 0，可能是首次访问、原文变化、缓存到期，或切换了翻译配置。

### 提示批量 JSON、段落数量或标识不匹配？

模型没有按要求返回批量结果。插件会停止插入异常译文，避免段落错位。可以调整提示词，或切换能遵循结构化输出指令的模型 / 引擎后重新翻译。

### 看不到新设置的效果？

点击 **保存配置** 后再使用。更改引擎、模型、提示词等会改变缓存匹配条件；如果只是想重新生成当前译文，请勾选 **忽略缓存重新翻译**。

更新代码后，需要同时重新加载扩展和刷新网页。

### 找不到“输入框翻译”的输入框？

如果想自己输入一段文字，请使用 **文本翻译**。

**翻译网页输入框** 是针对网页中已有的搜索框、评论框等：先点击它，操作按钮才会出现。

## 当前限制

- 网页翻译仅处理普通 HTTP / HTTPS 页面的主文档，暂不处理 iframe、网页自身的 Shadow DOM、PDF、图片文字或 Canvas。
- 整页翻译跳过代码块、表单、隐藏区域，以及带有 `translate="no"` 或 `.notranslate` 的内容。
- 每次开启网页翻译最多保留 200 个段落的译文；单段、划词和文本输入最多 4000 字符。
- AI 翻译请求目前有 25 秒超时限制；接口失败不会自动把原文发送给另一个服务。
- 复杂富文本、部分框架控制的输入框可能需要手动粘贴译文。
- Google / Microsoft 使用网页端免密钥接口，并非 Google Cloud / Azure 的商用 API，可能限流、变更或停止服务。

## 数据与隐私

翻译请求从扩展后台直连所选服务，没有开发者中转服务器、遥测或账号系统。开启整页翻译后，页面动态新增的内容也会继续参与翻译；仅选中文字不会发送请求。

| 数据 | 保存方式 |
| --- | --- |
| 常规设置、悬浮位置和网站关闭选项 | 当前浏览器本地存储 |
| API Key 和 AI 配置 | 扩展专属 IndexedDB，不发送给网页内容脚本；本地存储并非加密保险库 |
| 原文与译文缓存 | 扩展专属 IndexedDB，最多 10000 条、保留 30 天，可关闭或清空 |
| 独立页面草稿 | 通过浏览器会话内存临时传递，读取后删除，不写进 URL |

缓存不记录网页 URL，但原文和译文本身可能包含个人信息。敏感内容可以关闭缓存后再翻译，并按需清理已有记录。

接口地址由用户配置；请求和 API Key 会发送到该地址，请仅配置自己信任的服务。本地数据不会由插件同步到云端。

## 开发

运行代码为原生 JavaScript，无运行时第三方依赖。开发依赖用于验证和浏览器自动化。

```sh
npm ci
npm run build
```

修改后重新构建、重新加载扩展，并刷新测试网页。

仓库提供以下验证命令，开发时可按需执行：

```sh
npm test
npx playwright install chromium
npm run test:browser
npm run test:live
```

浏览器自动化使用独立用户目录；`test:live` 会向 Google / Microsoft 发送固定示例文本。现有测试不代表所有新增功能、浏览器及 AI 服务均已完成验证，AI 服务需要使用自己的配置验证。
